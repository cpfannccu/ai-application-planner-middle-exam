# 中級題庫解析編輯器與發布流程設計規格

日期：2026-09-02  
狀態：已由使用者核准

## 1. 目標

修正 115 年第一次中級科目 3 第 48 題的抽取邊界錯誤，並建立一套只在使用者電腦執行的解析編輯器。編輯器應讓非開發者能搜尋題目、撰寫安全 Markdown、加入圖片、審核及一鍵發布，同時保持公開 GitHub Pages 題庫為唯讀，避免訪客改動正式內容。

## 2. 已確認決策

- 解析輸入方式：離線網站編輯器。
- 儲存與發布：直接儲存至本機專案，經確認後一鍵驗證、提交並推送 GitHub。
- 解析格式：安全 Markdown，支援選用圖片，不允許任意 HTML 或 Script。
- 作答後顯示：答錯自動展開；答對預設收合；模擬考只在交卷後顯示。
- 內容狀態：草稿與已審核兩階段；只有已審核內容可進入正式網站。
- 編輯器不部署到 GitHub Pages，不提供公開投稿入口，也不在瀏覽器內保存 GitHub Token。

## 3. 範圍與非目標

### 3.1 本次範圍

1. 修正第 48 題與第 49～50 題共用情境的抽取邊界。
2. 建立本機解析編輯器、草稿保存、Markdown 預覽、圖片管理及審核狀態。
3. 建立受限制的本機發布流程。
4. 讓正式測驗網站載入及顯示已發布解析。
5. 增加資料、顯示、安全與發布回歸測試。

### 3.2 明確不做

- 不建立公開後端、帳號系統或訪客寫入 API。
- 不提供 AI 自動產生解析。
- 不讓公開網站直接提交解析或 GitHub Token。
- 不自動合併分歧 Git 分支。
- 不把「初級」資料或既有未追蹤舊網站檔案納入解析發布提交。

## 4. 第 48 題問題與修正設計

### 4.1 已確認原因

官方 PDF 第 17 頁中，第 48 題選項 D「模型過擬合」後接續一段 AOI 情境，該情境屬於第 49～50 題。抽取器同時辨識到：

1. 情境正文起點「某人工智慧團隊正在開發……」。
2. 較後方提示「請根據上述情境，回答第 49～50 題」。

現行演算法選擇最後一個候選起點，因此只把提示行移至第 49～50 題，卻把 AOI 情境正文留在第 48 題選項 D。

### 4.2 修正規則

- 找到未來題號範圍提示後，先尋找該提示之前、且其後續文字能涵蓋範圍提示的情境正文候選。
- 若存在情境正文候選，優先選擇距離範圍提示最近的正文起點；不得選擇範圍提示本身。
- 若不存在正文候選，才以範圍提示行作為共用內容起點。
- 第 48 題選項 D 必須精確結束於「模型過擬合（Overfitting）」；AOI 情境及回答範圍提示必須同時附加至第 49、50 題。
- 驗證器新增「前題選項不得包含下一組共用情境」回歸規則及此題的固定測試案例。

## 5. 系統架構

### 5.1 本機啟動器

- 路徑：`tools/explanation-editor/`。
- Windows 使用者雙擊 `啟動解析編輯器.cmd`。
- 啟動器呼叫 Python 標準函式庫伺服器，僅綁定 `127.0.0.1`，選擇未占用的本機埠並開啟瀏覽器。
- 每次啟動產生高熵工作階段權杖；所有寫入與發布 API 都必須攜帶權杖。
- 編輯器及伺服器不包含在 `site/`，因此 GitHub Pages 不會部署它們。

### 5.2 編輯器前端

編輯器分成三個工作區：

1. 題目清單：年度、梯次、科目、題號、關鍵字及狀態篩選。
2. 題目預覽：題幹、四個選項、官方答案及既有題目圖片。
3. 解析工作區：Markdown 編輯、即時安全預覽、圖片加入／移除、審核與發布控制。

### 5.3 本機工作資料

- 草稿保存在 Git 忽略的 `local-data/explanations-workspace.json`。
- 草稿圖片保存在 Git 忽略的 `local-data/explanation-assets/`。
- 寫入採暫存檔加原子替換；每次成功寫入前保留上一版備份。
- 編輯器另外使用 `localStorage` 保存尚未送達本機伺服器的短期輸入，重新連線後再同步。

### 5.4 正式網站資料

- 已發布解析：`site/data/explanations.json`。
- 已發布圖片：`site/assets/explanations/<question-id>/`。
- 測驗網站同時載入 `questions.json` 與 `explanations.json`，以穩定題目 ID 合併。
- `explanations.json` 載入失敗或單筆資料無效時，題目仍可正常作答；只略過受影響解析。

## 6. 資料模型

### 6.1 本機工作檔

```json
{
  "schema_version": 1,
  "updated_at": "2026-09-02T12:00:00+08:00",
  "items": {
    "115-1-L-S3-Q048": {
      "status": "draft",
      "markdown": "本題答案為 **D**……",
      "images": ["draft-image-01.png"],
      "updated_at": "2026-09-02T12:00:00+08:00",
      "published_revision": null
    }
  }
}
```

允許狀態只有 `draft` 與 `reviewed`。編輯已發布內容時，自動回到 `draft`，但正式網站保留上一個已發布版本。使用者必須重新標記為 `reviewed` 才能更新正式版本。

### 6.2 公開解析檔

```json
{
  "schema_version": 1,
  "generated_at": "2026-09-02T12:30:00+08:00",
  "items": {
    "115-1-L-S3-Q048": {
      "markdown": "本題答案為 **D**……",
      "images": ["assets/explanations/115-1-L-S3-Q048/image-01.png"],
      "updated_at": "2026-09-02"
    }
  }
}
```

公開檔不包含草稿、工作備註、GitHub 權杖或本機絕對路徑。取消發布必須是獨立、明確且需確認的操作；將已發布內容改成草稿不等同取消發布。

## 7. Markdown 與圖片

- Markdown 支援段落、標題、粗體、斜體、清單、行內程式碼、程式碼區塊及連結。
- 使用隨專案保存的 Markdown 解析器與 HTML 清理器，不依賴公開 CDN。
- 清理器禁止 Script、事件屬性、`javascript:` URL、任意 iframe 及未允許 HTML。
- 外部連結使用新分頁並加上 `noopener noreferrer`。
- 圖片可由拖放、剪貼簿或檔案選擇加入。
- 只接受 PNG、JPEG、WebP；驗證實際 MIME、檔案大小與像素上限，不只看副檔名。
- 圖片檔名由系統產生，不直接採用使用者檔名；所有路徑必須留在該題目的指定目錄。
- 移除已發布圖片時，只有在沒有任何已發布解析引用後才從公開資產目錄刪除。

## 8. 編輯與審核流程

1. 使用者啟動離線編輯器。
2. 搜尋或篩選題目並開啟完整預覽。
3. 輸入 Markdown；內容以短延遲自動保存為本機草稿。
4. 加入圖片時先複製至本機草稿資產，再更新工作檔。
5. 標記「已審核」前驗證內容非空、圖片存在、Markdown 可安全渲染。
6. 題目清單顯示：未撰寫、草稿、已審核未發布、已發布、已發布後修改。
7. 使用者可繼續編輯其他題目，不會因單題尚未完成而阻擋全部工作。

## 9. 一鍵發布流程

1. 取得 Git 遠端狀態；若本機 `main` 落後、分歧或遠端無法確認，停止發布並顯示處理方式。
2. 驗證題目 ID 均存在於 `questions.json`，Markdown 可清理、圖片存在且輸出路徑安全。
3. 以目前公開檔為基底，只套用本次已審核更新與明確取消發布項目；草稿不改變既有正式版本。
4. 原子產生 `site/data/explanations.json`，並複製／整理已引用圖片。
5. 顯示新增、更新、取消發布及圖片變更摘要，再要求使用者確認。
6. 只 stage `site/data/explanations.json` 與 `site/assets/explanations/`；不得使用 `git add .`。
7. 建立固定格式提交，例如 `content: update question explanations`，推送 `origin/main`。
8. 監看 GitHub Pages workflow；成功後顯示正式網址，失敗時保留本機資料及可重試資訊。

Git 命令使用參數陣列執行，不經 shell 字串拼接。發布端點需要工作階段權杖、正確本機 Origin 與再次確認值。

## 10. 正式網站顯示規則

- 解析區標示「非官方解析」及最後更新日期。
- 即時練習與錯題複習：答錯自動展開，答對預設收合，使用者可手動切換。
- 模擬考：交卷前不把解析插入畫面；交卷後於檢討區提供解析。
- 沒有解析的題目不顯示空解析元件。
- 解析圖片採延遲載入；單張缺圖顯示替代訊息，不中止其他解析或測驗。
- 網站原有「不提供非官方解析」文字改為清楚說明解析由本站整理、並非官方內容。

## 11. 安全與失敗處理

- 伺服器只綁定 loopback，不接受區域網路或外部連線。
- 所有寫入路徑使用解析後絕對路徑檢查，拒絕 `..`、絕對輸入路徑、符號連結跳脫與非白名單目標。
- 請求限制大小，JSON 結構與字串長度均需驗證。
- 無效圖片、無效題目 ID、空白審核內容與重複資產名稱均拒絕保存或發布。
- 本機工作檔損壞時保留原檔並嘗試讀取最近備份，不以空檔覆蓋。
- Git push 失敗不回滾本機解析；若提交已建立，重試時避免重複提交相同內容。
- Pages 部署失敗不影響 repository 內已推送資料，介面提供 workflow 連結。
- 公開解析檔載入失敗不影響題庫載入、計時、作答或學習紀錄。

## 12. 測試與驗收標準

### 12.1 題庫修正

- 第 48 題選項 D 不包含 AOI 情境或第 49～50 題提示。
- 第 49、50 題皆包含完整 AOI 共用情境。
- 六份試卷各 50 題，總數 300；答案、CSV、JSON 與 92 張既有題目圖片一致。
- 既有共用題幹與跨頁圖片案例均通過回歸測試。

### 12.2 編輯器

- 搜尋、篩選、切題、草稿自動保存、重新啟動恢復均正常。
- 草稿不進入公開 JSON；已審核內容可發布；修改已發布內容不會立即覆蓋正式版本。
- 明確取消發布可移除正式解析，且不誤刪仍被引用圖片。
- Markdown 惡意 HTML、事件處理器與危險 URL 均被移除。
- 圖片加入、替換、移除、錯誤格式及超限情況均有測試。
- 非本機來源、錯誤權杖及路徑跳脫請求均被拒絕。

### 12.3 發布與正式網站

- 發布只 stage 解析公開檔案，不包含 `初級/`、舊網站檔或其他工作樹變更。
- 分支落後或分歧時停止，不自動 merge、reset 或覆寫。
- 即時練習答錯自動展開、答對預設收合；模擬考交卷前看不到解析。
- 解析載入失敗不阻擋作答；缺圖只影響單張圖片。
- 桌面與手機版均無橫向溢位，長解析與程式碼區塊可閱讀。
- 推送後 GitHub Pages workflow 成功，首頁、解析 JSON 與解析圖片公開網址回應正常。

## 13. 相容性與後續擴充

`questions.json` 保持既有結構，解析改由獨立檔案按 ID 合併，因此重新抽取官方題庫不會覆蓋人工解析。未來如需增加作者、參考來源或解析版本，可在 `explanations.json` 升級 schema；本次不預先加入未使用欄位。
