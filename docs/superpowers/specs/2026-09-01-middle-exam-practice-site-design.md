# AI 應用規劃師中級題庫網站設計規格

日期：2026-09-01  
狀態：已由使用者核准

## 1. 目標

將目前六份「中級」官方歷屆試題轉換為可重複使用的靜態題庫資料，並把原有 Google Sheets／Google Apps Script 題庫網站改造成可由 GitHub Pages 公開提供的自我測驗網站。

本階段不處理「初級」題庫。網站不需要登入，任何人都可透過網址使用；每位使用者的進度只保存在自己的瀏覽器中。

## 2. 已選定方案

### 2.1 架構

- 公開平台：GitHub Pages。
- 前端：純 HTML、CSS、JavaScript，不使用 React、Vite 或其他建置工具。
- 題庫來源：靜態 JSON。
- 個人進度：瀏覽器 `localStorage`。
- 備份方式：學習紀錄可匯出／匯入 JSON。
- 不設後端、帳號、雲端資料庫或跨裝置自動同步。

### 2.2 未採用方案

- 繼續以 Google Apps Script／Google Sheets 為正式執行環境：雖然表格維護方便，但載入速度、介面自由度與資料耦合不符合這次目標。
- 建立後端登入與資料庫：目前收益不足以抵銷成本、維運與隱私負擔。

## 3. 題庫範圍

本次處理下列六份中級官方試題：

1. 114 年第二次，中級科目 1：人工智慧技術應用與規劃。
2. 114 年第二次，中級科目 2：大數據處理分析與應用。
3. 114 年第二次，中級科目 3：機器學習技術與應用。
4. 115 年第一次，中級科目 1：人工智慧技術應用與規劃。
5. 115 年第一次，中級科目 2：大數據處理分析與應用。
6. 115 年第一次，中級科目 3：機器學習技術與應用。

每份試卷預期 50 題，實作時必須以 PDF 實際內容驗證，不能只依預期數量假設成功。

## 4. 使用者體驗

### 4.1 首頁流程

使用者先選擇測驗模式，再選題範圍：

- 完整歷屆試卷：依年度、梯次與科目選擇一份官方試卷。
- 跨年度隨機組卷：依科目抽取 10、20 或 50 題。
- 錯題複習：從本機錯題紀錄產生題組。

首頁應說明進度只保存在目前瀏覽器，並提供學習紀錄匯入／匯出入口。

### 4.2 答題版型

採用「專注單題＋題號面板」：

- 主區域一次顯示一題，包含題幹、圖片、四個選項與上一題／下一題操作。
- 桌面版右側顯示題號面板，標示未答、已答與目前題目。
- 行動版將題號面板移至題目下方或可展開區，不使用固定高度或橫向溢位。
- 顯示目前題數、總題數、作答進度與模式需要的時間資訊。
- 所有可操作控制支援鍵盤與足夠的觸控尺寸。

### 4.3 三種測驗模式

#### 即時練習

- 作答後立即顯示正確／錯誤狀態及官方答案。
- 題目與選項順序可隨機排列。
- 不強制計時。
- 不自動跳題，讓使用者自行閱讀結果後再前進。

#### 模擬考試

- 固定 50 題、90 分鐘。
- 保留官方題目與選項順序。
- 交卷或時間結束前不公布答案。
- 重新整理頁面後可從本機紀錄續答，計時以保存的開始／截止時間計算，不能因重新整理重置。
- 交卷前提示未作答題數。

#### 錯題複習

- 錯題寫入本機錯題紀錄。
- 每題保存連續答對次數。
- 連續答對兩次後自動移出錯題庫；再次答錯時重新加入並歸零。
- 若沒有錯題，顯示清楚的空狀態，不產生空白測驗。

## 5. 題目順序與身分識別

- 每題使用穩定且不隨排序改變的 `id`，格式如 `114-2-L-S1-Q018`。
- 題目或選項隨機排列時，答案判定仍使用選項代碼對應，不可依畫面索引判斷。
- 完整歷屆試卷在模擬考模式保留官方順序。
- 隨機題組應記錄本次抽題結果與排序，重新整理後不得重新抽取。

## 6. 資料模型

標準題目欄位：

| 欄位 | 用途 |
| --- | --- |
| `id` | 全題庫唯一且穩定的題目識別碼 |
| `year` | 民國年度 |
| `session` | 該年度梯次 |
| `level` | 固定為中級 |
| `subject_code` | 科目代碼 |
| `subject_name` | 科目名稱 |
| `question_number` | PDF 官方題號 |
| `question` | 可搜尋的題幹文字 |
| `option_a`～`option_d` | 四個官方選項文字 |
| `answer` | 官方答案 A～D |
| `images` | 零到多張題目圖片的相對路徑 |
| `source_pdf` | 來源 PDF 檔名 |
| `source_page` | 來源 PDF 頁碼 |
| `category` | 保留欄位，第一版空白 |
| `difficulty` | 保留欄位，第一版空白 |
| `explanation` | 保留欄位，第一版空白 |

JSON 中 `images` 為字串陣列。CSV 與 Excel 中以分號連接多個相對路徑。題目文字中的換行必須以合法 CSV／JSON 格式保存。

網站資料可使用頂層中繼資料與 `questions` 陣列，例如：

```json
{
  "schema_version": 1,
  "generated_at": "2026-09-01",
  "questions": []
}
```

## 7. 圖片策略

採混合式轉換：

1. 題目與選項盡可能保存為可搜尋文字。
2. 圖表、公式、流程圖、程式碼畫面或其他無法可靠文字化的資訊獨立輸出為 PNG。
3. 若 PDF 排版無法可靠拆分，保存完整題目區域截圖，避免遺失判題必要資訊。
4. 圖片使用相對路徑，確保本機預覽與 GitHub Pages 均可載入。
5. 同一題可有多張圖片。
6. 網站圖片載入失敗時顯示替代文字與缺圖提示，但不使整份測驗中止。

建議路徑：

```text
assets/questions/114-2/subject-1/q018-01.png
assets/questions/114-2/subject-1/q018-full.png
```

檔名只使用 ASCII 小寫、數字與連字號，避免部署環境及網址編碼問題。

## 8. 輸出檔案

### 8.1 網站 JSON

- 一份標準化 `questions.json` 作為網站唯一題庫來源。
- JSON 內容不可依賴 Google Sheets 或 Apps Script 執行時環境。

### 8.2 CSV

- 每份官方試卷各輸出一份 UTF-8 BOM CSV，共六份。
- 欄位順序固定，便於日後合併與程式處理。

### 8.3 Excel

輸出一份整合工作簿，至少包含：

- `全部題庫`：所有題目的一致欄位表格。
- 六份依年度／梯次／科目拆分的試卷工作表。
- `欄位說明`：資料字典與允許值。
- `資料檢核`：各試卷題數、缺少答案、缺少選項、重複 ID、圖片不存在等摘要。

工作簿應使用清楚的表頭、凍結窗格、自動篩選、合理欄寬與換行，不以合併儲存格承載題庫資料。

## 9. 本機學習紀錄

建議以版本化物件保存：

```json
{
  "schema_version": 1,
  "active_session": {},
  "mistakes": {},
  "attempt_history": []
}
```

- `active_session`：目前題組、排序、答案、模式、開始／截止時間與所在題號。
- `mistakes`：題目 ID、錯誤次數、連續答對次數、最近作答時間。
- `attempt_history`：每次完成測驗的範圍、分數、用時與完成時間。
- 匯入時驗證格式版本與必要欄位；無效檔案不得覆蓋既有紀錄。
- 匯入成功前先建立現有紀錄的記憶體備份，若寫入失敗則保留原資料。

## 10. 錯誤處理

- 題庫 JSON 載入失敗：顯示重新載入提示與錯誤狀態，不呈現空白頁。
- 題庫結構錯誤：列出可辨識的資料檢核訊息，停止開始測驗。
- 圖片載入失敗：顯示題目 ID 與缺圖提示。
- `localStorage` 不可用或容量不足：仍允許暫時作答，但提示本次進度可能無法保存。
- 倒數計時以絕對截止時間為準，避免背景分頁或睡眠造成計時漂移。
- 匯入學習紀錄失敗：顯示原因，既有紀錄保持不變。

## 11. 公開網站與內容說明

- 網站標示題目來源年度、梯次、科目與來源 PDF。
- 顯示「非官方練習網站」聲明，避免被誤認為官方服務。
- 不在第一版加入非官方解析；`category`、`difficulty`、`explanation` 保持空白。
- 原始 PDF 是否放入公開儲存庫，應與部署檔案分開決定；網站只依賴經整理的題庫資料及必要圖片。

## 12. 驗證與完成標準

### 12.1 題庫

- 六份試卷皆成功轉換。
- 逐份核對實際題數、題號連續性、四個選項與官方答案。
- 所有 ID 唯一。
- 所有 `images` 路徑存在，並人工抽查圖片裁切完整性。
- JSON、六份 CSV 與 Excel 的核心欄位值一致。

### 12.2 網站功能

- 三種模式均可完整開始、續答與結束。
- 完整試卷與 10／20／50 題隨機組卷皆可使用。
- 模擬考固定 90 分鐘，重新整理不重置計時。
- 即時練習正確判題且不強制自動跳題。
- 錯題連續答對兩次後移除；再次答錯可重新加入。
- 學習紀錄可正確匯出並在清除紀錄後重新匯入。
- 手機寬度 320px 起不出現內容遮擋或水平溢位。

### 12.3 部署準備

- 所有網站資源使用相對路徑。
- 在本機靜態伺服器與 GitHub Pages 路徑前綴下皆能載入。
- 專案提供清楚的本機預覽、資料更新與 GitHub Pages 發布說明。

## 13. 實作邊界

第一版不包含：

- 初級題庫。
- 登入、會員與雲端同步。
- 後端 API 或資料庫。
- AI 或人工補寫解析。
- 題目分類與難度標註。
- 教師管理後台或多人共同編輯。
